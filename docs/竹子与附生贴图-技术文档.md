# 竹子（bamboo）与附生植物贴图选择 · 技术文档

> 本文覆盖本轮新增的两项能力：
> 1. **新植物种类「竹子」+ 竹子特有参数**（竿数 / 竹高 / 竿径 / 丛基高 / 外倾角 / 节数 / 侧枝 / 竹叶…）；
> 2. **附生植物内置贴图选择**（从内置叶片卡片库挑一张给蕨类团 / 垂藤用）。
>
> 与渲染后端相关的内容（WebGPU/WebGL/Node 后端、HUD 绘制调用口径）见
> `docs/WebGPU-渲染后端-技术文档.md`（其中第 7 节解释了"绘制调用持续增长"不是 bug）。

---

## 0. 一句话结论

竹子**没有**另写一套生成器：它被实现成一组"生成前展开"的特有参数，
在 `buildTree()` 入口把 `params.bamboo` 翻译成通用的 `trunk / branches / leaves / bark`，
因此风场、蒙皮、节点表、LOD、选择、导出、自检全部原样复用；
竹节环是**贴图级**效果（树皮贴图 + 由节数反推的 UV 重复），不生成实体几何。

---

## 1. 为什么不能只写一个"物种 patch"

| 通用模型的假设 | 竹子的实际形态 | 直接照抄会怎样 |
| --- | --- | --- |
| 一根主干 + 逐层递减的分枝 | 一丛近乎平行的细竿（每竿都是"主茎"） | 竿数只能写死，面板改不了 |
| `applyStage` 把 `lengthRatio` 夹到 `[0.04, 1.2]` | 竿长 = 竹高 ÷ 丛基高，通常 > 1.2 | 竹高设 9 m 只能长出 1~2 m |
| 主干不长叶（`spawnLeaves` 只在 `buildBranch` 里调用） | 每根竿上都有叶 | 若把第一根竿当主干 → 得到一根秃竿 |
| 树皮是"粗糙/白桦/松鳞" | 革质光滑 + 等距竹节环 | 竿看起来像橡木棍 |

所以做法是：**参数组 + build 时展开**。

- 参数组：`params.bamboo`（13 个字段，`params.js` 里有完整默认值与单位注释）；
- 展开函数：`src/core/bamboo.js` 的 `applyBambooParams(params)`，非竹种原样返回（零开销）；
- 调用点：`src/core/treeBuilder.js` 的 `buildTree()` 顶部 `const P = applyBambooParams(params)`；
- 产物：一份"等价于用户设定"的通用参数树，后续流程完全不认识"竹子"这个概念。

`buildTree` 的返回值里多了一个 `effectiveParams`（= `P`），
`sceneManager.rebuild()` 用它创建/更新材质 —— 因为竹子的 `bark.uvScaleV` 是"由竹高与节数反推"的，
若材质继续用原始 `params`，改节数后几何与贴图密度会不一致。

## 2. 结构映射（bamboo → 通用树）

| 通用层 | 竹子里的含义 | 关键字段 |
| --- | --- | --- |
| 主干（trunk） | **根盘**：一块低矮的锥形根茎堆，**整个埋在地面以下**；竿从它的斜面上分出 | `height = baseHeight`（默认 0.4 m）、`baseY = -1.15 × baseHeight`、`baseRadius = rootSpread`（默认 0.8 m）、`fork.enabled = false` |
| L1（branches.level[0]） | **竹竿** | `count = culms`、`pitch = tilt`、`lengthRatio = height / baseHeight`、`taper = 0.42`、`gravity = 0`、`upBias = 0` |
| L2（branches.level[1]） | **侧枝**（上段、短、外张，承载大部分竹叶） | `startT = branchStart`（默认 0.42）、`count = twigs`、`lengthRatio = twigLength / height` |
| leaves | 披针形竹叶（竿上段 + 侧枝） | `shape = 'lance'`、`shapeMix = []`、`perBranch = leafPerTwig`、`size/width/droop` 直接来自竹子参数 |
| bark | 革质光滑面 + 竹节环贴图 | `procedural.style = 'bamboo'`、`vertexColorMix = 0.25`、`uvScaleV` 反推 |

### 2.1 两个必须为 0 的系数（踩过的坑）

`childDirection()` 里会先算 `gravity + phototropism + upBias`，再 `rotateTowardUp()`。
竿子原本只外倾 7°，若沿用乔木的 `upBias = 0.15 rad`（≈8.6°），**方向会被拉回竖直**，
于是 8 根竿几乎重合成一根粗绿柱（首版截图就是这个现象）。
因此竹竿层固定 `gravity = 0, upBias = 0`，外倾角完全由 `pitch = tilt` 决定。

### 2.2 竿长与"竹高"的关系

- `culmRatio = 竹高 / 丛基高`，在 build 时计算，不受 `applyStage` 的夹取影响；
- 场景里 HUD 的「树高」= 丛基高 + 竿长 + 少量长度方差/竹叶外扩，
  **通常比滑杆上的「竹高 (m)」高 0.3~0.9 m**（丛基与叶尖），这是刻意保留的自然差异；
- 竿长方差 `lengthVariance = 0.06`：一丛里各竿略有高低（0.06 时 HUD 误差控制在 ~8% 以内）。

### 2.3 生长阶段与季节如何作用
`applyStage`（`species.js`）末尾追加竹子缩放块：

| 参数 | 随阶段变化 |
| --- | --- |
| `bamboo.height` | `× stage.size` |
| `bamboo.culmRadius` | `× stage.radius` |
| `bamboo.culms` | 按年龄递增（树苗 5 → 成熟 8 → 古树 9） |
| `bamboo.nodeCount / twigs / twigLength / leafPerTwig / leafSize` | 随年龄递增 |

`applySeason` 末尾：

```js
p.bamboo.leafPerTwig = round(leafPerTwig × season.leafDensity)
```

原因：竹叶**不走** `leaves.perBranch` 的"叶预算"链路（竹子用 `bamboo.leafPerTwig` 独立控制），
如果不在这里乘季节密度，秋冬的竹子会和夏天一样密。

实测（seed 777，summer）：

| 阶段 | 竹子高度参数 | 实际 HUD 树高 | 竿数 | 叶数 | 全模三角面 | 蒙皮校验 |
| --- | --- | --- | --- | --- | --- | --- |
| 树苗 seedling | 1.15 m | 2.03 m | 6 | 252 | 3,692 | ok |
| 幼树 sapling | 2.66 m | 3.36 m | 7 | 420 | 4,284 | ok |
| 小树 young | 4.88 m | 5.61 m | 8 | 576 | 4,876 | ok |
| 大树 mature | 8.87 m | 9.95 m | 10 | 840 | 6,060 | ok |
| 古树 ancient | 11.71 m | 12.83 m | 12 | 1,008 | 7,244 | ok |

### 2.4 根盘：竿基不抱在一起（离散度）

现实中一丛竹子不是"所有竿从同一个点冒出来"：竿基散落在地下根茎堆的斜面上，
彼此相隔几十厘米，外圈竿比内圈竿更往外趴。实现方式是：

1. 主干从"细短茎"换成**根盘**（低矮锥形根茎堆）：`baseRadius = rootSpread`、`taper` 由 `rootScatter` 决定；
2. 竿基贴在根盘表面的不同高度（`startT 0.08 / endT 0.88 / startJitter = rootStagger / baseHeight`），
   而根盘是锥形 ⇒ **贴附高度不同 ⇒ 水平半径不同**，竿与竿的基部天然分开；
3. 竿径用 `cfg.radiusAbsolute = culmRadius`（见 §2.4.2）保证"外圈竿不会因为父枝更粗而变粗"。

#### 2.4.1 为什么要埋到地面以下

根盘整块用 `trunk.baseY = -1.15 × baseHeight` 下沉到地下（`treeBuilder.js` 的树干骨架起点由
`new THREE.Vector3(0, trunkBaseY, 0)` 决定）。原因是最初把根盘留在地面上时，1.6 m 宽的绿锥体
在透视里被读成"花盆/石头"（见 `.shots/bamboo-rs-lumpy.png`），竿看起来像插在一个盆里。
埋掉之后地面上只剩**每根竿自己的出土点**，脚部被地面平面遮住，离散感自然。

- `rootSpread = 0`（`clumped`）时**不埋**，退回旧行为：细短茎直接立在地面上，所有竿抱成一团；
- 因为竿基整体低了 ~0.3 m，HUD「树高」≈ 竹高 + 1.0 m（比不埋时略低），不要为它加竿长补偿
  （实测补偿会让 HUD 树高多出 1.5 m，已回退）。下沉取 1.15 倍而不是 1.0 倍，是因为 `startJitter` 会把个别竿抬到 t≈1，1.0 倍时那根竿的基部正好卡在地面上（实测露出小半截断口）。

#### 2.4.2 竿径必须用绝对值（通用链路改动）

`spawnChildren` 原先只按 `fr.radius × radiusRatio` 算子枝基部半径。竿基散开后父枝（根盘）
在贴附点的半径能从 0.25 变到 0.9，同一丛里最粗/最细的竿会差 4 倍。
因此 `treeBuilder.js` 新增 `cfg.radiusAbsolute`（米）：

```js
// treeBuilder.js spawnChildren
if (cfg.radiusAbsolute) {
  radius0 = max(0.0008, min(cfg.radiusAbsolute × variance, fr.radius × 0.92) × radiusScale)
}
```

上限 `fr.radius × 0.92` 是保留的：蒙皮按子枝根部直径在父枝环带上开孔，开口不能比父枝周长还大。
竹子侧给 `radiusAbsolute = culmRadius`、`radiusVariance = 0.08`。

实测（seed 777，`rootSpread` 0 / 0.5 / 1.0）：

| rootSpread (m) | 竿基水平半径（10 根） | 竿基半径（米） | 蒙皮 |
| --- | --- | --- | --- |
| 0（旧行为） | 0.06 ~ 0.19 | 0.045 ~ 0.051 | ok |
| 0.8（默认） | 0.30 ~ 1.14 | 0.045 ~ 0.051 | ok |
| 1.0 | 0.37 ~ 1.43 | 0.045 ~ 0.051 | ok |

（`flare` 只给 0.35：`flare = 1.25` 时最外圈半径会翻倍到 2 × rootSpread，已实测并改小。）

#### 2.4.3 三个参数的映射

| 参数 | 映射到 |
| --- | --- |
| `rootSpread` 根盘半径 (m) | `trunk.baseRadius`；0 → 退回 `culmRadius × 1.6` 细短茎 |
| `rootScatter` 竿基离散 0..1 | `taper = clamp(0.52 - 0.22 × s, 0.26, 0.6)`（锥度越大半径差越大）、`squash = 1 - 0.28 × s`（根盘椭圆）、`culmLevel.spread = 0.15 + 0.45 × s`（方位散布） |
| `rootStagger` 竿基错落 (m) | `culmLevel.startJitter = clamp(rootStagger / max(0.08, baseHeight), 0.02, 0.45)`（贴附高度差 ⇒ 半径差） |

## 3. 竹节环：贴图级，不是几何

### 3.1 环怎么画

`src/core/textures.js` 的 `makeBarkTextures({ style: 'bamboo' })`：

- 革质底：`h = 0.66 + (ridges-0.5)×0.08 + (grain-0.5)×0.04`（几乎没有粗糙树皮的深裂纹）；
- 环位置：`ring = |sin(fy·π·BAMBOO_NODE_BANDS)|`，`fy` 是贴图纵坐标（0..1）；
- 环的两层效果：
  - 节托（微凸）：`+= pow(1-ring, 2.5) × 0.07`；
  - 刻痕（深）：`-= pow(1-ring, 7) × 0.8`；
- 额外**压暗**：`ringDark = pow(1-ring, 7) × 0.55`，写颜色时 `× (1 - ringDark)`。

只做高度场不够：实测 10 m 外的竿上，3 px 宽的暗线完全看不见（首版截图无环）。
压暗系数是让"节"在正常观看距离能被认出来的关键。

### 3.2 环密度 = 每竿节数（反推 UV 重复）

`barkSkin.js L1015-1034` 的约定：**UV 以米为单位**（`v = 沿枝弧长`，`u = 周长`）。
所以"每米重复 R 次"满足：

```
竿高 H × R × BAMBOO_NODE_BANDS = nodeCount
→ R = nodeCount / (BAMBOO_NODE_BANDS × H)
```

- `BAMBOO_NODE_BANDS = 5`（`bamboo.js` 导出，`textures.js` 与本文件共用）;
- 成熟株：`nodeCount 14 / (5 × 9 m) ≈ 0.31` → 每 0.64 m 一道环；
- 早先写成 `nodeCount / BAMBOO_NODE_BANDS`（漏了竹高）会得到每米 40+ 道环，糊成一片。

材质侧通过 `effectiveParams.bark.uvScaleV` 拿到同一个数值（见 1 节的 `effectiveParams`）。

## 4. 竹子特有参数（面板 16 项）

组件：`src/components/BambooSection.vue`，挂载在 `AutoPanel.vue`（仅 `species === 'bamboo'` 时显示）。

| 参数 | 单位 | 默认 | 作用 |
| --- | --- | --- | --- |
| 竿数 `culms` | 根 | 10 | 一丛几根竿（1 = 单竿） |
| 竹高 `height` | m | 9.0 | 竿长基准（HUD 树高 ≈ 竹高 + 1.0 m） |
| 竿基半径 `culmRadius` | m | 0.048 | 竿基半径；同时作为 `radiusAbsolute`（竿径不随根盘半径变化） |
| 丛基高度 `baseHeight` | m | 0.4 | **地下**根盘高度；只决定竿基出土深度与竿长比例 |
| 根盘半径 `rootSpread` | m | 0.8 | 竿基在地下散开的水平半径；0 = 全部抱在一点（旧行为） |
| 竿基离散 `rootScatter` | 0..1 | 0.55 | 根盘锥度 + 椭圆度 + 方位散布，让竿基不成规整圆环 |
| 竿基错落 `rootStagger` | m | 0.12 | 每根竿出土高低差 ⇒ 贴附半径差 |
| 竹竿外倾角 `tilt` | ° | 7 | 离竖直方向的角度，越大竹丛越开张 |
| 每竿节数 `nodeCount` | 节 | 14 | 只用树皮贴图表达；改它 → `uvScaleV` 重新反推 |
| 侧枝起点 `branchStart` | 0..1 | 0.42 | 下段光竿、上段出侧枝（竹林最易认的剪影） |
| 每竿侧枝数 `twigs` | 枝 | 5 | 0 = 只有竿上叶 |
| 侧枝长度 `twigLength` | m | 0.9 | 侧枝伸出长度 |
| 每枝叶数 `leafPerTwig` | 片 | 14 | 竿上段 + 每根侧枝的叶数 |
| 竹叶长度 `leafSize` | m | 0.3 | 披针叶长 |
| 竹叶宽长比 `leafWidth` | — | 0.16 | 宽/长；竹子是细长披针叶 |
| 竹叶下垂 `leafDroop` | 0..1 | 0.55 | 叶片下垂程度 |

审计：`scripts/paramAudit.mjs` 为这 16 个字段加了"前置条件" `{ 'bamboo.enabled': true }`，
否则在非竹探针树上它们永远"无变化"（会被误报为失效参数）。

## 5. 附生植物：内置贴图选择

### 5.1 交互

`src/components/EpiTexturePicker.vue`（挂在 `LeafPanel.vue` 的「附生植物」Section 里，`TextureRow` 之后）：

- **批次** chip：① 秋色系 / ② 绿色系 / ③ 桦树 A … ⑰ 松针 B（来自 `LEAF_CARD_BATCH_NAMES`）；
- **叶形** chip：`#1 … #7`（`leafCardRows(batch)`）；
- **颜色变体** 缩略图：`TextureCard` 网格，点一下即写入 `params.epiphyte.texture`；
- **跟随树叶贴图**：把 `epiphyte.texture` 清成空串，回到原行为；
- 卡片用 `HEAD` 探测 + `content-type: image/` 过滤：
  dev server 对不存在的路径会 SPA 回退成 `200 + index.html`，只看 `r.ok` 会把 404 当成功。

### 5.2 为什么不新写一条材质通路

材质侧早已消费 `params.epiphyte.texture`
（`materials.js L1319-1330`：`epiKey → loadTexture({clamp, repairAlpha}) → u.uEpiphyteMap / uEpiphyteEnabled`，
换 key 时 dispose 旧图）。自上传是 dataURL、卡片是相对路径 URL，
两者都走同一个 `loadTexture`，所以这里**只写 URL，不动材质与几何管线**。

### 5.3 换贴图不重建几何

`params.js` 的 `serializeGroup()`：

- `geometry` 组把 `epiphyte.texture` 替换成空串（贴图变更不算几何变更）；
- `material` 组额外追加 `[['epiphyte.texture', ...]]`。

因此点缩略图只触发 `applyMaterialUpdate`，HUD 的「构建」耗时不跳、树的形态完全不变
（实测：点击前后 `构建 481.8 ms`、`树叶 11520` 均未变，附生卡片立即换图）。

### 5.4 一个顺手修掉的响应式坑

`LeafPanel.vue` 里 `epiphyte` 分组原本是普通对象引用（`const E = state.params.epiphyte`），
撤销/导入参数会整体替换 `state.params`，面板会写到已被丢弃的旧对象上。
已改成 `computed(() => state.params.epiphyte)`（与 `BambooSection.vue` 的写法一致）。

## 7. 验收与回归

```bash
node scripts/selftest.mjs        # 384 通过 / 0 失败
node scripts/audit-params.mjs    # exit 0，无"失效参数"
npm run check                    # mcp-selfcheck + code-review + selftest + audit + build 全绿
```

竹子专项探针（可直接粘进 node 控制台）：

```bash
node -e "import('./src/core/treeBuilder.js').then(async m=>{const {composeTree}=await import('./src/core/species.js');const t=m.buildTree(composeTree('bamboo','mature','summer',777));console.log({h:t.stats.height,spread:t.stats.spread,branches:t.stats.branches,leaves:t.stats.leaves,skin:t.skinStats.validation.ok})})"
```

实测基线（seed 777，大树/夏，默认 rootSpread 0.8）：`height 9.95 / spread 6.14 / branches 61 / leaves 840 / 全模三角面 11,100 / skin ok`。`rootSpread 0` 时冠幅回到 4.2 m 左右（竿抱成一团）。

界面回归：

1. 树种切到「🎋 竹子」→ 下方出现「竹子特有参数」16 项，改竿数/竹高/外倾角后点「⟳ 重建」立即变化；
2. 竿上能看到等距的深色竹节环（每竿约 14 道，改「每竿节数」后密度跟着变）；
3. 「树叶 → 附生植物 → 启用」后出现「内置附生贴图」，点任意缩略图 → 标签变「已选贴图」，
   蕨类团/垂藤换成该贴图，且「构建」耗时不增加（未重建几何）；
4. 把「根盘半径」拖到 0：所有竿立刻回到同一点出土（旧行为）；再拖回 0.8：竿基在地下散开、各自破土；\n5. 切其它树种：竹子参数区块自动消失，其余参数不受影响。

## 8. 明确未做的（边界）

1. **竹节不是实体几何**：没有节环的凸起网格、没有竹箨（鞘），只有贴图 + 法线；
2. **竹叶用程序化披针叶**（`shape: 'lance'`），没有复用叶片卡片库；
   —— 如果之后要竹子专用叶卡片，`bamboo.js` 里给 `leaves.texture` 写卡片 URL 即可，
   几何链路已经支持；
3. **竿顶不开口**：没有"中空竹筒"的端面，杆体仍是闭合管；
4. **不做开花/结果**：竹子开花是几十年一遇的事件，`fruit/flower` 在竹种里强制关闭；
5. **竿的节数不参与几何分段**：`nodeCount` 只影响贴图密度，不增加网格细分
   （否则三角面数会随节数线性膨胀）。
